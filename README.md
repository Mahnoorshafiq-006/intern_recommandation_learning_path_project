# intern_recommandation_learning_path_project
# Learning Path Recommendation System

A recommender that suggests **personalized learning paths for interns** using **Collaborative Filtering (Matrix Factorization)**. Each intern receives a step-by-step list of courses ordered from Beginner to Advanced, based on what similar interns took, finished, and liked.

> **Task objective:** Build a system to recommend personalized learning paths for interns.
> **Data needed:** Past intern learning patterns and course content metadata.
> **Model type:** Collaborative Filtering (Matrix Factorization).
> **Outcome:** Suggest custom learning modules for each intern.

## Dataset

The project uses two kinds of data. The course data is real. The intern history is synthetic.

| Data | Source | Type |
|---|---|---|
| Course content metadata | Kaggle **Online Courses** dataset (`Online_Courses.csv`, about 8,000 rows from Coursera, FutureLearn, Udacity, and Simplilearn). Only the **Coursera** rows with a category were used. | Real |
| Past intern learning patterns | Generated by `generate_from_coursera.py` on top of the real courses | Synthetic |

Kaggle dataset link: _add your Kaggle link here_

**Why synthetic intern data?** Real intern learning histories are private company data and are not publicly available. The generated history follows the same structure a real system would log (intern, course, rating, completion).

### Files used by the model

| File | Rows | Description |
|---|---|---|
| `data/intern_learning_history.csv` | 24,059 | Intern-course interactions: rating (1-5), completion %, completed flag, plus course details |
| `data/courses_clean.csv` | 1,000 | Cleaned course metadata: title, category, sub-category, type, level, duration, rating, viewers, URL |
| `data/interns.csv` | 800 | Each intern's main interest, second interest, and skill level (used only for sanity checks) |

### Data preparation steps
- Filtered the raw file to Coursera courses with a valid category.
- Translated 7 non-English category labels to English (for example `Negocios` to `Business`).
- Removed duplicate course titles.
- Parsed rating text (`4.9stars`) and viewer counts (`10,438`) into numbers.
- Converted duration text into estimated hours (weeks = 5 h, months = 20 h).
- **Derived a difficulty level** (Beginner / Intermediate / Advanced) from course type and duration, because the source has no level for Coursera rows.
- Kept the 1,000 most-viewed courses, with at least 30 per category where available.

### How the intern history was generated
- 800 interns, each with a main interest, a second interest, and a skill level.
- Each intern took 20 to 40 courses. Course choice is weighted by interest match, skill-level fit, and course popularity.
- Ratings depend on interest match, course quality, a per-intern bias, and random noise.
- Completion percentage is correlated with the rating.
- Result: 97% sparsity in the intern x course matrix, which is typical for recommender data.

## Techniques and Methods Used

### 1. Data engineering
- Data cleaning, text parsing, deduplication, category normalization
- Feature derivation (level, estimated duration)
- Synthetic data generation with controlled structure (interest groups, popularity bias, noise)

### 2. Exploratory data analysis
- Rating distribution, courses per intern, courses per category
- Sparsity analysis of the interaction matrix

### 3. Evaluation setup
- Random 80/20 train/test split of interactions
- **Baselines:** global mean rating, course mean rating, and a popularity ranking

### 4. Model A: Explicit Matrix Factorization (rating prediction)
- Biased matrix factorization trained with **Stochastic Gradient Descent (SGD)**
- Prediction: `rating = global_mean + intern_bias + course_bias + P[intern] . Q[course]`
- **L2 regularization** to reduce overfitting
- **Hyperparameter tuning** of the number of latent factors (5, 10, 20, 40)
- Metric: **RMSE**

### 5. Model B: Implicit Matrix Factorization (ranking)
- **Alternating Least Squares (ALS)** for implicit feedback (confidence-weighted matrix factorization)
- Positive signal: courses the intern took with rating >= 3
- Confidence: `1 + alpha * (rating / 5) * (completion / 100)`
- Hyperparameter tuning of latent factors (5, 10, 20), selected by Precision@10
- Used to rank all courses the intern has not taken yet

Why two models: Model A can only learn from courses an intern already took, so it ranks unseen courses poorly. Model B learns from which courses interns chose and finished, which is what ranking needs. Model A is kept to show an expected rating for each recommendation.

### 6. Ranking evaluation
- **Precision@10** and **Recall@10** on held-out liked courses (rating >= 4)
- Already-taken courses are excluded from recommendations
- Comparison against the popularity baseline

### 7. Learning path generation
- Top-N recommendations per intern
- Ordered **Beginner -> Intermediate -> Advanced**, best match first within each level

### 8. Cold-start handling
- For a new intern with no history, a **content-based fallback** recommends well-rated, popular courses in the chosen interest category, again ordered by level

### 9. Sanity check
- Share of recommended courses that match the intern's main interest, compared with random chance

## Results

Results from the included run (seed 42):

| Evaluation | Model | Result |
|---|---|---|
| Rating prediction (RMSE, lower is better) | Course-mean baseline | 0.944 |
| | Matrix Factorization (SGD) | **0.878** |
| Ranking, Precision@10 | Popularity baseline | 0.005 |
| | Explicit MF (SGD) used for ranking | 0.003 |
| | **Implicit MF (ALS, k=10)** | **0.026** |
| Ranking, Recall@10 | Popularity baseline | 0.010 |
| | **Implicit MF (ALS, k=10)** | **0.076** |
| Interest match of recommendations | Random chance | about 17% |
| | **Implicit MF (ALS)** | **88.5%** |

Precision values look small because each intern has only about 5 liked courses hidden in the test set among roughly 1,000 candidate courses. The models should be compared with each other, not against 100%.

**Key finding:** the rating-only model ranked worse than plain popularity, while the implicit model ranked about 5 times better. This is why the final system uses implicit matrix factorization to choose courses.

## How to Run

### Option 1: Google Colab (recommended)
1. Open `Learning_Path_Recommendation_System.ipynb` in Google Colab.
2. Click the **folder icon** on the left and upload `intern_learning_history.csv` and `courses_clean.csv` (and optionally `interns.csv`).
3. Run all cells from top to bottom.
4. `recommendations.csv` (8 courses for each intern) is created and downloaded at the end.

### Option 2: Local
```bash
pip install -r requirements.txt

# 1. (optional) regenerate the data from the raw Kaggle file
python generate_from_coursera.py Online_Courses.csv

# 2. run the project (reads the CSVs from ./data)
python learning_path_recommendation_system.py
```

## Limitations
- The intern learning history is **synthetic**, so results show that the pipeline works, not how it would perform on real interns. Interest patterns are built into the generated data, which likely makes results look better than real data would.
- Course level is **derived** from course type and duration, not taken from the source.
- Duration in hours is an **estimate** converted from weeks and months.
- Only 1,000 courses are used to keep the matrix at a manageable size.
- Evaluation uses a random split, not a time-based one.

## Future Work
- Replace the synthetic history with real intern learning logs.
- Add a hybrid model that combines collaborative filtering with course content (text of descriptions).
- Use prerequisite relationships between courses to build stricter learning paths.
- Add a time-based evaluation split and metrics such as NDCG and MAP.
- Wrap the recommender in a small web app (for example Streamlit).
